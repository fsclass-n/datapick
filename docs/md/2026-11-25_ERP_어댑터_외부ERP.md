# 2026-11-25 실제 ERP 적용을 위한 어댑터 계층 + 독립 미니 ERP

## 배경
- 데모 ERP(같은 서버 /erp-demo)만 있어 실제 ERP 적용 경로가 없었음 → 포트폴리오용으로 "대상별 차이를 설정으로 흡수하는 어댑터 구조"를 도입

## 구현
- `rpa/erp.py` 신설: `ErpAdapter` 인터페이스 + 구현체 2종
  - `WebFormAdapter`: Playwright 타이핑. 대상 화면의 url · 필드 셀렉터 맵 · 저장/결과/전표번호 추출 · 로그인 단계를 JSON 설정으로 외부화 (`ERP_CONFIG`: 파일 경로 또는 JSON 문자열)
  - `FileExportAdapter`: ERP 일괄등록용 엑셀에 행 누적 (`ERP_EXPORT_PATH`)
  - `ERP_ADAPTER` env로 선택(기본 web_form), 미설정이면 기존 데모 ERP 동작 유지
- `rpa/erp_typer.py`: 기존 CLI·type_record API 유지, 내부는 WebFormAdapter 위임(중복 제거)
- `documents.py` RPA 분기: `erp.submit_record()` 한 줄로 교체
- `rpa/erp_target.example.json`: 로그인 포함 대상 설정 예시
- `external_erp/main.py`: 별도 프로세스·도메인으로 띄우는 독립 미니 ERP(세션 로그인, 전표 등록/목록, /api/health). render.yaml 에 선택 서비스 주석 추가
- `.env.example`: ERP_ADAPTER · ERP_CONFIG · ERP_USERNAME/PASSWORD · ERP_EXPORT_PATH 추가

## 남은 과제
- 실제 ERP 대상 시에는 ERP_CONFIG 셀렉터 맵만 교체. 사내망/데스크톱 ERP는 로컬 에이전트 방식 필요(미구현, 한계로 문서화)
- external_erp 를 Render 에 별도 서비스로 올리면 운영 환경에서도 경계 넘는 연동 시연 가능

## 2026-11-27 후속 — ERP_CONFIG 설정 실패 대응
- 증상: Render env 에 긴 JSON 을 붙이다 잘려(Unterminated string) RPA 작업이 JSONDecodeError 로 실패
- 개선: `ERP_CONFIG` 는 파일 경로/JSON 문자열 모두 지원하되, `ERP_URL` env 가 설정의 url 을 덮어쓰고
  `login.url` 은 비어 있으면 `{url}/login` 으로 자동 유도 → 예시 파일 경로 + ERP_URL 만으로 연결 가능
- JSON 해석 실패는 ErpTypingError("ERP_CONFIG JSON 해석 실패: ...")로 명확히 표시
- `.env` 도 erp.py 에서 load_dotenv 로 읽어 CLI/직접 호출 시에도 동작
- 예시 파일에서 login.url 제거(유도 방식으로), render/env/README 갱신, 테스트 61 → 66
- Render 설정 최종 권장값: ERP_CONFIG=rpa/erp_target.example.json + ERP_URL=https://datapick-erp.onrender.com/ + ERP_USERNAME/PASSWORD
