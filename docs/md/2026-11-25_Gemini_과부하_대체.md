# 2026-11-25 Gemini 과부하 대응 (대체 모델 + 규칙 폴백)

## 배경
- 견적서 비교기 샘플 체험에서 "Gemini 호출 실패 (503, 4회 시도): high demand" 가 계속 발생
- 기존 재시도는 (2s→5s→10s) 총 4회, 약 17초 안에 끝나 무료 티어 과부하가 이어질 때 그대로 422 에러

## 변경
- `GEMINI_FALLBACK_MODEL`(기본 `gemini-2.5-flash-lite`) 설정 추가
  - `generate_structured` 가 재시도 소진·모델 404 시 대체 모델로 같은 호출을 다시 시도 (용량 풀이 달라 과부하 회피 효과)
  - `FAILOVER_STATUS = {429, 500, 503, 504, 404}`
- 두 모델 모두 실패하면 각 도구의 규칙 파서로 대체 (샘플 체험이 끊기지 않음)
  - 견적서 `extract_quote_rules` · 계약서 `review_contract_rules` · 건강검진 `extract_health_rules` · 문서 `parse_with_rules`
  - 결과 `engine` 은 실제 사용 엔진으로 표기 (모두 gemini 성공 시에만 `"gemini"`, 아니면 `"rules"`)
- `.env.example` 에 항목 추가

## 확인
- pytest 52 passed (대체 모델 전환 테스트 · 규칙 폴백 테스트 추가)

## 참고
- 규칙 폴백이 동작하면 결과 목록의 엔진 표시가 "Gemini" 대신 규칙으로 표시됨 → 장애 추적 가능
- 근본 해결은 아님: 무료 티어 과부하가 길어지면 규칙 결과 품질로 내려감. 유료 티어 또는 추가 백오프를 늘릴 수 있음
