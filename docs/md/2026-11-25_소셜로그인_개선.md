# 2026-11-25 소셜 로그인 개선

## 배경
- SNS 로그인 버튼 클릭 후 완료하지 않고 뒤로가기하면 스피너·비활성 상태가 그대로 남아 멈춘 것처럼 보임
- Google 버튼 클릭 시 `datapick-api.onrender.com/api/auth/oauth/google/login` 에서 Chrome "위험한 사이트" 차단 페이지가 뜸

## 원인
- `socialLogin` 이 `setBusy(provider)` 후 `location.assign` 으로 외부 페이지로 이동 → 뒤로가기 시 브라우저가 bfcache 에서 페이지를 복원해 React `busy` 상태가 그대로 남음
- Google Safe Browsing 가 `…/oauth/google/login` URL 을 위험 사이트로 등록 (다른 도메인에서 `google/login` 경로는 피싱 패턴으로 분류되기 쉬움). 도메인 전체가 아니라 해당 URL 단위로 플래그된 것으로 보임(`/docs` 는 정상 표시)

## 변경
- `GET /api/auth/oauth/{provider}/login` → `/api/auth/oauth/{provider}/start` 로 경로 변경 (콜백은 Google 콘솔 등록 그대로 `/callback` 유지)
- 같은 엔드포인트에 `?format=json` 추가 → 리디렉션 대신 `{ "url": "<제공자 인증 URL>" }` 반환 (state 쿠키는 동일하게 설정)
- `Login.jsx` `socialLogin`: `credentials:'include'` fetch 로 시작 URL을 받은 뒤 주소창 이동은 제공자(Google/Naver/Kakao) 페이지로 직접 수행 → 플래그된 API URL 이 탐색 경로에 나타나지 않음. 실패 시 기존 리디렉션 방식으로 폴백
- `Login.jsx`: `pageshow`(bfcache 복원)·`visibilitychange`(탭 복귀) 이벤트에서 `busy` 해제
- 버튼 호버 손가락 커서: `index.css` 전역 `button:not(:disabled){cursor:pointer}` (이전 커밋)

- TestClient: `…/start?format=json` → 200 + `{url}` + state 쿠키, `…/start` → 307 리디렉션

## 잔여 이슈
- Safe Browsing 플래그 자체는 Search Console 에서 도메인 소유 인증 → Security Issues → 검토 요청으로 해제 가능 (API 도메인은 HTML 파일 인증 라우트 추가가 필요)

## 후속 (같은 날): 쿠키 없는 경로의 state 검증 보강

### 증상
- SNS 로그인 완료 후 "로그인 요청이 만료되었거나 올바르지 않습니다" 오류로 로그인 실패

### 원인
- `?format=json` 프리패치로 받는 `dq_oauth_state` 쿠키가 사이트 간(fetch, onrender.com 은 PSL 이라 프런트·API 도메인이 cross-site) 응답이라 브라우저에 저장되지 않는 경우가 있음 → 콜백에서 state 쿠키가 없어 검증 실패

### 변경
- 서버가 발급한 state 를 `OAUTH_STATES`(메모리, TTL 600초, 1회용)로도 관리
- 콜백: 쿠키 있음 → 기존처럼 state 비교 / 쿠키 없음 → 프런트 `/oauth/callback?provider&code&state` 로 전달
- 프런트: 시작 시 받은 `state` 를 `sessionStorage`(탭 한정)에 보관 → 콜백에서 대조 → 일치하면 `POST /api/auth/oauth/{provider}/exchange {code, state}` 로 토큰 교환 (서버는 레지스트리에서 발급 여부 확인 후 팝)
- 이 구조는 시작한 브라우저와 state 를 바인딩하므로 쿠키 검증과 동급의 CSRF 방어 유지
- 직접 이동(폴백) 경로는 최상위 탐색으로 쿠키가 설정되어 기존 흐름 그대로 동작
