# 2026-11-17 UI 전면 개편 및 권한 모델 개편

플랫폼 표준 가이드(전역 레이아웃 · 도메인 맞춤 UI · 상용 푸터 · 관리자/테스트 관리자 권한)를 데이터 입력 자동화 플랫폼에 맞게 적용.

## 1. 전역 레이아웃
- `components/layout/SiteLayout`: 모든 페이지에 글로벌 헤더 + 푸터 + 원형 Top 버튼
- 최초 접속(`/`)은 항상 메인(랜딩) 페이지. 로그인 후에도 `/` 는 메인, 앱은 `/dashboard`
- 헤더 2가지 상태
  - 비로그인: 주요 기능 · 작동 방식 · 활용 사례 · 보안·권한 · FAQ (메인 섹션 해시 이동) + 로그인 / 무료로 시작하기
  - 로그인: 대시보드 · 문서 처리 (+ 관리자: 회원 관리 · 모니터링), 역할 배지, 사용자 정보, 로그아웃
- 모바일: 햄버거 ↔ X, 우측 드로어 (비로그인 시 로그인/가입 버튼 포함)
- 테스트 관리자 로그인 시 헤더 아래 '읽기 전용' 안내 배너

## 2. 도메인 맞춤 UI (메인 페이지)
| 섹션 | 내용 |
| --- | --- |
| Hero | 핵심 문구 + 실제 처리 흐름을 재현한 제품 화면(원문 → AI 추출 → 엑셀/ERP 전표) |
| 지원 형식 | 입력(PDF · 이미지 · EML · HTML · TXT · 본문) / 출력(Excel 원장 · 웹 ERP) |
| 작동 방식 | 수집 → 해석 → 검수 → 입력 4단계 |
| 주요 기능 | 구조화 추출, 단계적 OCR, 사람 검수, 엑셀 원장, ERP 자동 타이핑, 운영 모니터링 |
| 활용 사례 | 재무·회계 / 구매·총무 / 영업지원 (입력 문서 → 결과) |
| 보안·권한 | 운영 관리자 · 테스트 관리자 · 일반 사용자 비교, 보안 조치 |
| FAQ | 5문항 (지원 문서, AI 오류 대응, ERP 연동, 데이터 전송, 관리자 차이) |

- 실제로 구현 · 검증되지 않은 수치(정확도, 고객사 로고 등)는 넣지 않음

## 3. 디자인 시스템 표준화 (`src/index.css`)
- 타이포 스케일: `text-display`(56px) · `text-title`(32px) · `text-heading`(20px) · `text-body`(15px) · `text-caption`(13px)
- 레이아웃: `container-page`(최대 1280px, 좌우 16/24/32px), `section-y`(랜딩 섹션 64/80/96px), `page-y`(앱 화면)
- 섹션 라벨: `eyebrow` (처음에 `overline` 으로 만들었으나 Tailwind 기본 text-decoration 유틸리티와 충돌해 줄이 그어짐 → 이름 변경)

## 4. 푸터 표준
- 브랜드 소개 + SNS(GitHub) / 제품 · 리소스 · 고객지원 · 정책 4열
- 하단 사업자 정보 영역: 운영자, 고객센터(GitHub Issues), "개인 포트폴리오 프로젝트로 별도 사업자 등록 정보 없음"을 그대로 표기 (가짜 사업자 정보 미기재)
- 이용약관(`/terms`) · 개인정보처리방침(`/privacy`) 페이지 신설: Gemini API 전송, 저장 위치(TiDB · Render), 공개 테스트 계정 주의 사항 명시
- 우측 하단 원형 To the Top 플로팅 버튼 (스크롤 320px 이후 표시)

## 5. 권한 모델
| 역할 | 진입 | 권한 |
| --- | --- | --- |
| `admin` 운영 관리자 | `/admin/login` 에서 `ADMIN_TOKEN` 입력 → `POST /api/auth/admin-login` | 전체 CRUD, 회원 권한 변경 |
| `test_admin` 테스트 관리자 | 로그인 화면 '테스트 관리자' 버튼 | 관리자 화면 조회만, 쓰기 요청 403 |
| `user` 일반 사용자 | 가입 · OAuth · '일반 사용자' 버튼 | 본인 문서 |

- **서버 강제**: `deps.get_current_user` 단일 진입점에서 `test_admin` 의 GET/HEAD/OPTIONS 외 요청을 403 으로 차단 → 새 API 를 추가해도 자동 적용
- **토큰 검증**: `secrets.compare_digest`, 같은 IP 5회 실패 시 10분 차단(429), 토큰 미설정 시 503
- **공개 계정 보호**: 테스트 계정 권한은 `backend/app/test_accounts.py` 기준으로 서버 기동 시마다 복원, 권한 변경 API 로 변경 불가(400)
- **보안 이슈 해소**: 기존에는 로그인 화면에 비밀번호가 공개된 `admin@datapick.io` 가 실제 관리자 권한을 가져, 누구나 회원 권한을 바꿀 수 있었음 → 읽기 전용으로 전환
- 프런트: 테스트 관리자는 업로드 · 검수 저장 · 재해석 · 삭제 · RPA · 권한 토글 비활성 + 안내 문구. Mock 모드도 동일 규칙(운영 관리자 로그인은 Mock 에서 비활성)

- pytest 30개 통과 (신규 8개: 토큰 로그인, 잘못된 토큰 · 차단, 토큰 미설정, test_admin 역할, 조회 허용, 쓰기 5종 차단, 테스트 계정 권한 고정, 기동 시 권한 복원)
- 프런트 lint 오류 0, build 성공

- Mock 빌드: 테스트 관리자 토글 5개 전부 비활성, 업로드 영역 비활성, 운영 관리자 로그인 안내 확인
- 데스크톱(1440) · 모바일(390) 화면 확인
